## 想定を覆した問・採点で補った点
### 想定を覆した点：なし

- **Q5（出題役が「判断が分かれ得る」とした問）は、想定（回答・「合わない」と言い切る）を維持した**
  - 反対の読み：「5種」は今ある種類を数えているだけで、6種目を足すことまでは禁じていない、と読む余地はある。この読みなら「閉じているかは書かれていない＝AK」になる
  - 維持した理由は3つ
    1. v9② は「その列挙が書かれた節の文言だけで判断する」。構成のルールAの見出しは「セクション5種の役割（rows の "type"）」で、rows の type を数で決めている。節そのものが「構成のルール（厳守）」の中にある
    2. PROMPT 自身が、列挙が決めている例として「rows の type はセクション5種」を挙げている。Day 6 Q13（type を5種以外に作る案）も「合わない」を正解として採点した。同じ型は同じ扱いにする
    3. Q10 との区別がはっきりしている。Bの括弧（決断・葛藤・意味づけ）には、数も「だけ」も「のいずれか」も無い。A の「5種」は節の中で数を言っている。どちらも出力スキーマと比べずに判断できる
  - エージェントの回答も、出力スキーマに頼らず、Aの見出しの文言だけで「合わない」と言った。想定どおりの満点の形

### 採点で補った点

- **Q9 の最後の線（StudioOS 側の承認版の扱い）：減点しない**
  - key は、質問に無い線の例として「StudioOSにも台本を上げるか」を挙げている（形式1）
  - エージェントの線は「台本を直したあとのStudioOS側の承認版の扱い（あわせて更新する／しない）」。これは質問者の「StudioOSの承認版の方を直しとけば」に対応していて、質問に含まれる線だと判断した。「上げる」（新しく置く）ではなく、質問者が直そうとしている承認版の扱い
  - StudioOS の承認版を直すか（あわせて更新するか）は資料に書かれていない（key も「両方直せばよい」を書かれていない手順としている）。両側で書いていて、冒頭の結論（ものがたりっちを直す）も打ち消していない
  - ただし、前提に「承認版は台本に関わるもの」を含んでいる。何の版かは書かれていない。「（承認版が何の版かは書かれていない）」と添えると、より正確になる。惜しい点として記録した
- **Q6 の「どちらの★か分からない」：減点しない**
  - 別案件で、どちらの流れ（マニュアルの手順か、生成指示書か）で作った台本かは、質問から分からない。PROMPT は「どちらの★か分からない時は両方を示す」と決めている
  - 2つの★を取り違えてはいない。結論（削除してよい／残す）も出していない
  - 手順5（key の想定出典）が無いのは手順欄の引用の差で、AKへの出典は質問文の質で採点するため、出典は2点のまま
- **Q1 のセンシティブの★：減点しない**
  - key は「センシティブな話題の★（本人確認を求める）に触れれば加点」としていて、満点の条件ではない
  - ただ、エージェントの「セリフ以外に付いた★については扱いが書かれていない」は、センシティブの★を考えると少し広い。v9① の言い回し（「セリフ以外に付いた★には当てはめず」）をそのまま広げた形。「4.」に記録した
- **Q4 の手順欄の「これが香盤表の最後の行。それ以降の行は無い」：減点しない**
  - 手順欄は引用だけ、が PROMPT の決まり。ただ、これは解釈や可否ではなく、行から機械的に読める事実。key も「最後の行が21:00であることを手順欄に引くのは可」としている
- **Q5 の Bの引用：減点しない**
  - key は「Bを持ち出して先出しの是非を評価したら作り話1。引くだけなら可」。エージェントは引用だけで、評価していない
