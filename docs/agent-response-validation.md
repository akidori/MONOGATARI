# 質問回答の形式検証（2026-10-05）

基点：main `a8cd10d9`。PR49とは独立した修正。正式ナレッジ・agent/PROMPT.md・評価原文は変更しない。

## 再現と範囲

旧`worker/src/index.js`の`/判定[:：]\s*AKへ/.test(text) ? "AKへ" : "回答"`は、判定行なしの「回答: 本人がOKなら公開して大丈夫です。\n出典: qa.md 2026-10-04」、単独の「わかりません」、未知判定、回答本文欠落を確定回答にしていた。逆に正常回答の引用「判定: AKへ」でAK通知側に入った。空回答は従来も502で拒否しており、空回答まで確定していたわけではない。

`agent/eval/FINAL_REPORT.md`の「出力の扱い」は、判定行が無い等の形式不正を回答にしない方針。今回の本人指示ではさらに「未知はnull保留、外部通知しない」と指定されたため、その指示を優先する。情報不足としてAKへ回すことと、回答形式の検証失敗を混同しない。

## 修正

- `src/agent-response.js`でWorker/UI共通の形式検証。先頭の独立した判定行を必須とし、値は回答/AKへだけ。重複判定・重複項目・相反する項目を拒否する。
- 回答は非空の回答と出典、AKへは非空の理由と質問文を必須とする。行内引用、`>`引用、フィールド内の閉じたコードフェンス内の判定文字列は制御として読まない。裸の判定行が再登場した場合は曖昧として拒否する。回答全体をコードフェンスで囲む形式は契約外として拒否する。
- 形式不正・空・出力打切りはHTTP502、`code: AGENT_RESPONSE_INVALID`、詳細`validationError`、`verdict:null`、`notified:false`。未検証本文は返さない。構造化エラーと`console.warn("agent_response_validation_failed", validationError)`で識別でき、ログに質問・本文・顧客情報は載せない。運用ログの保管設定は今回変更しない。
- 不正時は回答/AK統計・inbox・通知・メールへ進まない。試行したLLM呼出しの日次利用回数は従来どおり加算する。`bumpStat`自身も未知判定を回答数に加算しない。
- UIは不正な200応答も拒否し、原質問を入力欄に保持する。既存ローカル履歴の不正本文は削除せず保留表示にする。正常結果のみ履歴へ保存する。
- 通知済み表示は新応答の`notified:true`（アプリ内通知の保存成功）の場合だけ。既存履歴や旧Workerの応答は通知未確認と表示。メール配信成功とは言わない。
- 正常な回答/AKへ、明示的provider refusalの既存AK経路、API接続失敗/502は維持。理由/質問が欠けたAK出力は勝手に補って通知せず、形式検証エラーとして原質問を保持する。
