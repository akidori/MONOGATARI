# ものがたりっち Premiereプラグイン整理メモ（Claude用）

更新日: 2026-10-03
目的: Claudeで要件・設計・開発順を整理するための現状ブリーフ。

## まず押さえること

「ものがたりっちのPremiereプラグイン」は、Premiere内で編集作業を支援し、案件・工数・素材アップロード・修正指摘をものがたりっちとつなぐ拡張機能として案内されている。アプリ内マニュアルは既に多数の機能を前提にしている。

ただし、今回確認できたチェックアウトでは、ものがたりっち本体のプラグインソースは存在しない。`/Users/ak/premiere-auto-editor/uxp-plugin/` にはAdobe UXPの別拡張「Auto Editor」（`com.teamharu.autoeditor`）があり、パイプライン成果物のXML/SRT/画像をPremiereへ読み込む小さなパネルである。これは、ものがたりっちのマニュアルが指す「ものがたりっち」パネル全体と同一実装だとは確認できない。既存機能の記述は、主にものがたりっちの操作マニュアルとWorker APIから復元したもの。

また「プレミア／Premium」が有料プラン名を指す場合、その料金・権限・機能差を定義した一次資料は見つかっていない。以下ではPremiere Pro向けプラグインとして記述し、課金プランは未確定事項にする。

## プロダクト上の目的と設計方針

- Premiereから離れずに、編集者が案件情報を確認し、定型編集・チェック・修正対応を進められる。
- AIは候補・検索語・チェック結果を出す。画像の適合性、権利、誤字修正、構成・表現などの最終判断は編集者が行う。
- 元シーケンスや元クリップを保全する。自動配置・一括操作は結果を明示し、可能な範囲で新規シーケンス／Undoで戻せる。
- ものがたりっちを案件・動画確認・共有アップロードの正本として扱い、Studio OSを制作工程・納期の正本とする。
- 小さな状態更新はまとめて送信する。Worker側の説明ではKV書き込み上限を考慮し、停止時と10分ごとに工数を集約送信する。
- APIキー等の秘密値はプラグイン画面やログへ露出させない。MCPはBearerキーで認証し、読取キーと書込キーを分ける。

## 想定ユーザーと利用場面

- 編集者: 案件選択、素材の取り込みと配置、テロップ・画像・翻訳、チェック、修正、書き出し。
- ディレクター／制作責任者: 案件と編集状況の確認、工数の予定・実績把握、納品物レビュー。
- Premiere Pro上で案件素材を編集し、完成動画をものがたりっちの確認画面へアップロードする。

## 現在資料から確認できる機能

### 案件・制作連携

- ものがたりっち案件一覧から案件を選択。完了済み案件は一覧から除外する設計（`list_scripts` がStudio OS完了案件へ`done:true`を付与）。
- 案件の工数表とStudio OS上の現在工程を取得する。
- Premiere内で編集の現在作業・完了済み作業を記録する。
- 工程の予定分数と実績分数を読み書きする。標準予定がなければ予定分数を標準値にも登録する。
- 編集作業タイマー（マニュアル上の「砂時計」）を想定。実績は一定間隔／停止時にまとめて保存。
- 共有済み案件の完成動画アップロードリンクを取得する。

### Premiere内の編集補助（マニュアルに記載）

- 素材を案件へ取り込む／タイムラインへ並べる・同期する。
- テロップ: 音声文字起こしからSRT生成、SRTを並べる・整列、横中央揃え、翻訳。
- ピック: 同じ時間帯・開始位置・選択範囲のクリップを対象トラックから選び、一括で有効化／無効化／削除／リップル削除。
- 画像: 発話・文字起こしを解析して挿入候補と検索語を作り、Pixabayから候補素材を取得。任意でタイムライン配置。
- 整列: テロップの端をカット境界へ補正。選択素材をテロップ等の境界へ一括配置。
- チェック: 誤字脱字候補、クリップ間の1フレーム隙間、テロップ端ズレ、セクション尺を点検。
- 修正: ものがたりっちの時間指定コメントを一覧表示し、選択すると該当時刻へ移動。
- 書き出し: Premiere書き出しから案件・動画名を指定し、ものがたりっちへアップロード。

注: 上のUI機能はアプリ内ヘルプの操作説明に基づく。各機能が現行プラグインの最新ビルドで動くか、対応するソース・テストはこの確認範囲では検証できていない。

## ものがたりっち側の接続仕様（確認済み）

- MCP入口: `worker/src/mcp.js`（`POST /mcp`、JSON-RPC 2.0 / Streamable HTTP）。
- 認証: `Authorization: Bearer ...`。読取キーは読取専用ツール、書込キーは読取＋更新系ツール。
- ツール: `list_scripts`, `get_script`, `update_script`, `create_script`, `get_upload_link`, `get_effort`, `log_effort`, `set_edit_state`, `set_planned`。
- 工数データは`eff.steps`と`eff.edit`に保存。編集状態は現在作業と完了作業の配列を持つ。
- `get_upload_link`は案件の共有が未発行なら`share_missing`を返す。共有リンクを勝手に新設せず、ものがたりっち上で共有を発行する前提。
- `list_scripts`はStudio OSで制作完了の案件に印をつける。Studio OS読取に失敗した場合は、案件を誤って隠さない。
- 工数書込は頻繁な小刻み書込を避け、定期集約する方針。

## 別リポジトリにある確認済みのUXP拡張

場所: `/Users/ak/premiere-auto-editor/uxp-plugin/`。ManifestはPremiere Pro 25.0以上、UXP Manifest v5、パネル名Auto Editor。

- パイプライン出力フォルダを読んでXML、SRT、素材をPremiereへ読み込む。
- XMLを読み込んで配置、カット／インサート／字幕マーカーを追加。
- SRTとインサート画像を取り込み、Adobe Media Encoderへ書き出す。

これはものがたりっち連携API（案件一覧・工数・修正・アップロード）を呼んでいる実装とは確認できていない。開発を続ける前に、このUXP拡張を拡張対象とするのか、別の非公開／別ディレクトリのものがたりっちプラグインが正本なのかを特定する必要がある。

## 現状の非機能・安全上の要点

- ものがたりっちMCPの書込ツールは、台本変更・工数追加・編集状態更新など、種類ごとに分離する。
- 台本更新は`baseUpdatedAt`による競合検知に対応。プラグインで案件データ自体を更新する必要性は現資料から確認できない。
- 誤操作時にPremiereのUndoが効く一括編集を優先。元シーケンスを直接破壊しない機能はマニュアル上、新規シーケンスを作る例がある。
- 画像候補は必ず人が内容・利用可否を確認してから使う。
- 字幕翻訳は時刻を維持し元SRTを変更しないが、固有名詞と文字量は人が確認する。
- 共有リンク未発行、API接続失敗、競合、保存失敗を成功扱いにしない。
- Premiereのバージョン・OS・UXP API制限・ネットワーク断時のオフライン動作は、別途受け入れ条件を決める。

## 未確定・要件化が必要な点

1. 対象プラグインの正本リポジトリと現在のリリース版はどこか。
2. 「プレミアのプラグイン」はPremiere Pro用UXP拡張全体か、課金プランPremiumを指すのか。
3. v1で必須にする機能と、現行機能のうち継続・停止・再設計するもの。
4. UXPだけで完結する機能、ローカル補助サービスが要る機能、Worker APIを使う機能の境界。
5. 案件選択、アカウント接続、キー配布・失効、複数ユーザー、権限、アップデート方法。
6. 工数タイマーの計測定義（再生中のみか、アイドル検知、スリープ／Premiere終了時、手動修正、複数案件同時起動）。
7. API障害・オフライン時のキュー保存と再送、二重計上防止、競合解決。
8. Premiere／OSの対応範囲、最低要件、配布・署名方法。
9. Premiumが課金プランなら、無料との差、対象ユーザー、価格、利用上限、返金・解約はまだ根拠資料なし。
10. 機能別の受け入れ基準とテスト素材・対応シーケンス条件。
