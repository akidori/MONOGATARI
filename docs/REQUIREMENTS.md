# ものがたりっち 要件定義書

更新日: 2026-07-29  
版: 0.9（現行実装の整理版）

## 1. 目的

「ものがたりっち」は、YouTubeを中心とした映像制作において、企画、取材、構成台本、香盤表、素材、動画確認、納品までを1案件の中でつなぐ制作管理アプリである。

主な目的は次のとおり。

1. 制作情報がチャット、メモ、表計算、動画サービスへ散らばる状態を減らす。
2. 企画から納品までの情報を同じ案件データで連動させる。
3. 制作者、編集者、クライアントが必要な範囲だけ共有・共同編集できるようにする。
4. 動画確認の再生・シーク・コメントを軽快にする。
5. 一般利用者へ展開するとき、運営者のストレージとAPI費用へ集中しない構成にする。

## 2. 対象範囲

### 2.1 対象

- チャンネル／クライアント管理
- 一日密着・トーク系動画の案件管理
- 企画、取材メモ、構成台本、香盤表
- 素材と確認動画
- コメント、共有、共同編集
- 納品情報と制作進行連携
- AIによる整理、生成、校正
- ログイン、保存、外部サービス接続

### 2.2 現時点で対象外

- 会計、請求、契約管理
- 本格的な動画編集
- Google Driveへの実ファイル保存
- 利用者別AIキーによる本体AI実行
- 一般公開向けの課金・プラン管理
- 組織単位の詳細なロール管理

## 3. 想定利用者

| 利用者 | 主な目的 |
|---|---|
| 制作責任者／ディレクター | 企画から納品まで案件全体を管理 |
| 構成作家 | 取材メモと構成台本を編集 |
| 撮影担当 | 香盤表、場所、時刻、撮影完了を確認 |
| 編集者 | 素材取得、確認版アップロード、コメント対応 |
| クライアント | 企画、台本、動画を必要な範囲で閲覧・修正 |
| 運営管理者 | 外部API、保存基盤、利用上限、障害を管理 |

## 4. 利用形態

### 4.1 未ログイン利用

- 同一端末・同一ブラウザ内で利用できること。
- 案件はlocalStorageへ保存されること。
- 別端末への自動同期は行わないこと。
- ブラウザデータ削除時に消失する可能性を明示すること。

### 4.2 ログイン利用

- Googleアカウントで本人確認できること。
- 案件を利用者単位のクラウド領域へ保存できること。
- 別端末でも同じ案件一覧を取得できること。
- 初回ログイン時にローカル案件を移行できること。
- GoogleログインがGoogle Drive保存を意味しないことを明示すること。

### 4.3 共有利用

- 案件全体または指定タブだけを共有できること。
- 閲覧用と編集用を区別できること。
- Googleアカウント招待とURL共有を使い分けられること。
- 共有の対象、権限、保存先、費用負担を確認できること。

## 6. データ要件

### 6.1 主要データ

| データ | 主な内容 |
|---|---|
| User | Google sub、氏名、メール、画像 |
| Channel | 名称、基本情報、コンセプト、競合、注意点 |
| Project | 案件名、形式、テーマ、メタ情報 |
| Plan | タイトル、サムネ文言、参考動画、添付 |
| Hearing | セクション、質問項目、回答 |
| Script Row | ロケーションまたはシーン、原稿、尺、時刻 |
| Asset | ファイルキー、URL、カテゴリ、メタデータ |
| Video Version | R2キー、Stream UID、YouTube ID、状態 |
| Comment | 投稿者、本文、時間位置、返信、対応状態 |
| Delivery | 動画URL、公開情報、サムネ、納品素材 |
| Connection | provider、接続状態、用途、契約者、期限 |

### 6.2 保存先

| 条件 | 保存先 |
|---|---|
| 未ログイン案件 | ブラウザlocalStorage |
| ログイン案件JSON | Cloudflare Workers KV |
| 共有スナップ・コメント | Cloudflare Workers KV |
| 運営基盤のファイル | Cloudflare R2 |
| 運営基盤の動画変換 | Cloudflare Stream |
| 利用者自身の動画 | 利用者のCloudflare Stream |
| リアルタイム共同編集 | Cloudflare Durable Objects |
| Google Drive | 現在は保存先として未使用 |

### 6.3 保持・削除

- 動画のゴミ箱保持は7日間を基本とする。
- 共有データ、案件データ、素材の保持期限は公開前に規約として確定する。
- アカウント削除と全データエクスポートは未実装であり、一般公開前の必須要件とする。

## 8. 非機能要件

### 8.1 性能

- 通常画面はデスクトップ・スマホで実用的な速度で表示すること。
- 動画はHLSを優先し、シーク待ちを短くすること。
- 大容量アップロードはブラウザから保存先へ直接または分割送信すること。
- 自動保存は編集操作を阻害しないこと。

### 8.2 可用性・復旧

- 通信失敗時に未保存であることを明示すること。
- KV上限到達時に保存済みと誤表示しないこと。
- PWAキャッシュ更新で旧版が残り続けないこと。
- 動画誤削除に復元猶予を設けること。

### 8.3 セキュリティ

- secret、APIキー、OAuth tokenをリポジトリやブラウザ画面へ出さないこと。
- OAuth refresh tokenは暗号化してサーバー側へ保存すること。
- ファイルアップロードURLは期限と対象を制限すること。
- ファイル完了時に保存先の実サイズを検証すること。
- AI、アップロード、共有作成へ利用者別レート制限を設けること。
- 将来、セッションをlocalStorageからHttpOnly Cookieへ移行すること。

### 8.4 ユーザビリティ

- PCとスマホの主要操作を維持すること。
- 画面上の用語だけで保存先と共有範囲を誤認しないこと。
- 長い文書で現在地と移動先が分かること。
- 破壊的操作は確認または復元手段を持つこと。

### 8.5 アクセシビリティ

- アイコンだけのボタンに名称を持たせること。
- キーボードフォーカスを視認できること。
- 色だけに依存せず状態を伝えること。
- ツールチップはホバーだけでなくフォーカスでも表示すること。

## 9. 一般公開の受け入れ条件

以下を満たすまで、不特定多数への無制限公開は行わない。

1. AI APIをログイン必須にし、利用者・日単位の回数上限を設ける。
2. ファイル容量、動画時間、保存量を利用者単位で計測・制限する。
3. ゲストアップロードを案件ごとの明示許可制にする。
4. 管理者がAI、アップロード、共有作成を停止できること。
5. 保存先、保持期限、削除方法、費用負担を画面と規約に明記する。
6. アカウント削除、データ削除、データエクスポートを提供する。
7. 利用規約とプライバシーポリシーを公開する。
8. Cloudflare OAuthをprivate環境で検証後、public化する。
9. APIキー・token・個人情報がログへ出ないことを確認する。
10. バックアップと障害復旧手順を定める。

## 10. 推奨提供プラン

### 個人版

- 自分のCloudflare Streamまたは将来のGoogle Driveを利用
- 自分のAI APIキーを利用
- 運営者のストレージ・AI費用へフォールバックしない
- 小規模な共有と共同編集

### 運営版

- 運営のR2、Stream、AIを利用
- 容量、動画時間、AI回数に明示的な上限
- チーム共有、レビュー、進行連携
- 月額または案件単位の料金
