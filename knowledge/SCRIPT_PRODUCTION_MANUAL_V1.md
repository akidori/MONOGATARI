# 構成台本制作マニュアル v1

この文書を、人物密着ドキュメンタリーの構成台本制作の長期ナレッジの正本とする。
Flip-LABにも同内容が登録されているが、あちらは参照用のミラーであり、更新はこちらを起点に行う。

## 台本の保存先とMCPの使い方

台本の実体（正本）はものがたりっち（MCP: `monogataritch`）が持つ。

- 読む: `get_script`（id は共有ID または案件ID）
- 書く: `update_script`（`data` は `{ name?, channel?, meta?, rows? }`。`baseUpdatedAt` に直前の `get_script` で得た `updatedAt` を必ず付ける＝競合検知のため）
- **書く前後にアプリをリロードすること**。ものがたりっちを開いたままだと、あとからの保存で上書きされる事故が起きる

## 台本を作るときの入力テンプレ

依頼者は以下を埋めて渡す（空欄OK。空欄はClaudeが仮置きし、仮置きした箇所には★を付ける）。

```
【台本id】（ものがたりっちで先に新規作成しておく）
【撮影日・場所・尺】
【CV】
【0問目】この人はどんな顔をしているか（一言）
【Q2】苦しみの奥にある感覚
【Q5】クライマックスだと思う場面
【Q11】普通の人役
【NG】出してはいけない話・人
【文字起こし】
```

## Claudeが台本を作る時に1回でやること

1. **前提4CHECK**
   - 撮れるものになっているか
   - 現場でしか分からない問いが残っていないか
   - クライマックスとCV（キャッチヴァリュー／核となる価値）が整合しているか
   - 入口（冒頭）から最後まで同じ約束を守れているか
2. **質問13（全13問を必ず出す）** — 「認識OS 質問13」。台本・タイトルを「認知更新装置」として設計するための13問。Flip-LAB（`lab_questions(domain: "台本設計")`）が正本の最新版を持つため、内容に確信が持てない時は都度そちらを引く。2026-09-26時点の版を以下に記録する（スナップショット）：
   1. この人（ターゲット）は何に苦しんでいるのか（顕在的な問題）
   2. その苦しみの奥にはどんな「O（言葉になる前の感覚）」があるのか（身体感覚・違和感・居心地の悪さ）
   3. その人は世界をどういう世界だと思っているのか（世界モデル・認識OS）
   4. その世界モデルは今どこで揺れているのか（矛盾・違和感・認知的不協和）
   5. 敵は「誰」ではなく「何」なのか（古い認識／社会構造／思い込み／制度／文化／自分自身）
   6. 本当に欲しいものは何なのか（願望・欲求・理想）
   7. 本当に恐れているものは何なのか（喪失・拒絶・孤独・失敗など）
   8. その人はどんな状態でこの動画を見るのか（時間／場所／心理状態）
   9. 冒頭で何を見ると身体が反応するのか（クリック理由／サムネ／タイトル／第一印象）
   10. 何が未解決だから最後まで見続けるのか（情報ギャップ／認識ギャップ／感情ギャップ）
   11. 主人公はどんな壁にぶつかるのか。そしてそれはターゲットの壁とどう重なるのか（自己投影ポイント）
   12. 最後にどんな世界モデルへ更新されるのか（認識OSのアップデート）
   13. 見終わった人は「誰に」「何と言って」共有するのか（共有理由・口コミ・文化形成）
3. **ピクサー7段（日常→喪失→敵対→気づき→戦い→喪失②→統合）＋スパイン＋2段クライマックス（仕事の答え→人生の答え）**
4. **場所割り・時間軸**
5. **台本**（会話調・文字起こし照合・仮置き箇所には★を付ける）
6. **ものがたりっちへ書き込み**（`update_script`、`baseUpdatedAt` を付けて）
7. **残り**の提示：
   - 残り2割（AKの判断が必要な点）
   - 撮影当日のインタビューシート
   - タイトル案

## 必ず守るルール

- 0問目の顔（一言で表した第一印象）に合わせる。人物を実際より暗く描かない
- 前半はインパクト優先。経歴・過去は後半か、移動中インタビューへ回す
- 質問→答えの組をひとつずつ確認し、その質問への答えになっているか検証する。次の質問は前の答えから自然に出る疑問にする。唐突な話題転換をしない
- セリフを削りすぎない。スパインが「だから」で繋がるか確認する
- Claudeが作った（仮置きの）セリフには★を付ける（撮影当日に本人から引き出す／削除／別表現に置き換える候補という意味）
- 演出案を実態として書かない。反転（気づき・転換）の主体は演者本人であり、演出側が代わりに転換を書かない
- 尺の目安は1秒5文字。文字数が足りない時は映像表現で太らせる（セリフを水増ししない）
- センシティブな話題は★を付けて本人確認を求める。迷ったら入れない

## 密着ドキュメンタリーを対話で作る時の進め方（2026-10-07 石野華鳳さん案件で確立）

「Claudeが台本を作る時に1回でやること」を、AKと対話しながら進める時の順番と、各段でAKから出た指摘をまとめる。1段ごとにAKの確認を取ってから次へ進む。返答は短く、要点が一瞬で分かる形にする。

### 順番

1. **1日の流れ**を表で出す（パート・中身・尺）
2. **ストーリースパイン**
3. **ピクサー7段**（敵の反転・守りたいもの3回・2段クライマックスを添える）
4. **JOKER理論**（差異・敵・未解決の連鎖・社会テーマ・ヒキ）
5. **文字起こしと照合**（最後まで読み直し、食い違いを一覧にする）
6. **1日の流れを台本用に詳細化**（AKが出した撮影順に合わせる）
7. **過去の台本を読んでから、ものがたりっちへ書き込む**
8. **フィードバックはClaudeのチャットで受け、ものがたりっちの台本へ直接反映する**（別ドキュメントを正本にしない）

### スパイン

- 大事なのは「変遷と文脈」。経歴の説明で済ませず、なぜ今の活動をしているのか、発端になった時期の思いまで入れる。抜けると「つまらない人」になる
- 本心や苦労など言葉にできない感情は、台本に言葉を書かない。「余白」として、どこで・どんな状況でその話に近づくかだけ決め、問いを1つ置いて待つ
- 本人の語りにない因果や転機を作らない。成り行きは成り行きのまま書く（事実より美しくしない）
- 各セクションに、インパクトのある内容か映像的なシーンを必ず1つ置く（LPの作り方と同じ）
- 攻撃しない方針の案件でも、変遷に必要な文脈は入れる。「悪い人がいる」ではなく「苦しんでいる人がいる」を軸にする

### ピクサー7段

- 気づきは、本人の認識が最初に変わった体験に置く（石野さんの例：祖父に連れて行かれた施設での体験）
- 気づきの後、すぐに変わらなくてよい。その「間」も事実どおりに書き、戦いの手前に新たな気づきを置く

### JOKER理論

- 冒頭でスタートとゴールだけを見せ、間を見せない（「こんな人が、なぜ」の未解決を作る）
- 敵は人ではなく構造。社会的に、全世界の人が共感できる社会問題や需要を内包させ、ヒキを作る
- 業界の闇は抽象化して世界の構造に落とし込む。動画内ではその業界の話しかしていないのに、視聴者が自分の世界に重ねて共感できる状態を狙う。抽象的な言葉（社会構造・どの業界も同じ等）は動画内で誰にも言わせない
- 例：書道界 →「内輪の人たちが、受け手を置き去りにした独自の正解を作っている。本当は初めて見る人が『すごい』と分かってこそ意味がある」
- 主人公がそれを言う説得力は、前のセクションで先に見せておく（中を通ってきた経歴・学んできた量・実際に人が変わる場面）
- 各セクションは、回収と同時に次の未解決を1つ置いて終わる
- 弱者の苦しみを強く描きすぎない。0問目の顔が明るい人は、落差を「笑える落差」として置く

### 文字起こし照合で必ず見る点

引き継ぎメモや途中の要約を根拠にしない。必ず文字起こしの原典に当たる。石野さん案件で実際に見つかった食い違い：

- **話者**：名言が本人の発言か、同席者（配偶者・担当者）の代弁か。代弁は台本のセリフにせず「★取材」にして当日本人から引き出す。台本上は（夫）など話者を明記する
- **数字の主語**：再生数などの数字が、演者のものか別の動画・別の人のものか
- **場所と時系列**：別々の場所・時期の出来事を1つにまとめていないか
- **合意と検討中の区別**：「前向きに考える」「撮ってみて無理ならカット」は合意ではない。当てにできない場所（自宅など）に構成を依存させず、代わりに撮れる場所を決めておく
- **本人の立場**：同席者の言葉（例「もっと自由でいい」）と、本人の立場（例「勉強しないともったいない」）を混ぜない
- **形容の対象**：本人が何について言った言葉か（自分自身か、自分の作品か）

### 場面設計

- 紹介パートは、いつも使っている道具の紹介と一緒に撮る。実物とともに値段や歴史が分かる
- 紹介はインタビューに近い形で話し始めてもらう。撮影後に冒頭へ入れ替えられるよう、前後の場面に触れない答えで完結させる
- 夫婦・家族の場面は、会話が面白ければ決め打ちの絵を置かず「流れのまま」と書く
- 似た題材を2か所で撮る時は役割を分ける（例：自宅の道具＝歴史、用品店＝選ぶ目を言葉にする）
- 締めをどこに置くかは、当てにできる場所で決める（自宅が不確かなら、仕事の現場で締める）

### ものがたりっちへ書き込む前

- `list_scripts` で、その案件の枠がすでに無いか確認する（空のひな形が作られていることがある）。あれば新規作成せず、その枠に書く
- 同じチャンネルの完成済み台本を2本ほど `get_script` で読み、書式を合わせる
- 書式：◼ 問い → 答え（話し言葉のまま）／★取材：当日引き出すこと／※要確認：事前確認／（ ）インサートの絵／【テロップ】／▶【編集】。冒頭ダイジェストは `meta.highlight`、設計メモとNGは `meta.note`、ピークとCVは `role`

## ものがたりっちAIエージェント（構想・2026-09-26時点でStep 0調査中）

台本制作の相談窓口として、以下の役割分担で動く想定。

- **答える範囲**：このマニュアル＋今扱っている案件の台本・香盤表・取材メモ・NG事項。回答には必ず出典（マニュアルのどの節か／どの案件のどの記録か）を付ける
- **AKに回す範囲**：お金・スケジュール・クライアント対応・構成変更・センシティブな判断・このマニュアルにもものがたりっちにも書いていないこと
- **学習ループ**：AKが答えた内容は `knowledge/qa.md` に追記し、以後は同じ質問にエージェント自身が出典付きで答えられるようにする
- **継続判断**：2週間ごとの質問数と、「エージェントが直接答えた件数」対「AKへ回した件数」の比率で、この仕組みを続けるか見直す

このセクションは実装が固まり次第、詳細（呼び出し方・権限・ログの形）をこのマニュアルへ追記する。
